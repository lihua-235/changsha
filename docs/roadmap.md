# 长沙美食 POI 项目 · 制作步骤清单

> 核心理念：**数据 → 信号 → 实验 → 服务 → 前端**。顺序不可颠倒。
> 每个 Phase 都有验收标准，未通过不进下一阶段。

---

## 总览

| Phase | 时间 | 目标 | 是否可跳过 |
|---|---|---|---|
| 0 数据侦察 | 3 天 | 搞清到底能拿到什么字段 | 不可 |
| 1 候选池 + 标注规范 | 2–3 周 | 建立可靠的 ground truth | 不可 |
| 2 信号可行性验证 | 2 周 | **生死检查点** | 不可 |
| 3 文本与实地信号 | 寒假 3 周 | 补上最难的两块数据 | 可降级 |
| 4 实验与对比 | 2 周 | 出论文级结果 | 不可 |
| 5 Java 后端服务 | 6–8 周 | 可用 API | 不可 |
| 6 前端与演示 | 3 周 | 可访问 Demo | 可简化 |

---

## Phase 0 · 数据侦察（3 天）

目标：**在写一行业务代码之前，先确认数据边界。**

- [ ] 注册高德开放平台个人开发者账号，创建应用，拿到 Web 服务 Key
- [ ] 分别调通 4 个接口各一次：关键字搜索、周边搜索、地理编码、路径规划
- [ ] 以"五一广场"为中心、半径 3km、关键词"餐饮"，拉一次 POI 列表，存成 JSON
- [ ] 拉一次"文和友"这类具体店铺的详情，看返回什么
- [ ] 逐字段盘点：**有 / 没有 / 只有部分**，重点确认
  - [ ] `rating`（评分）
  - [ ] `cost`（人均）
  - [ ] `opentime`（营业时间）
  - [ ] `tag` / `keytag`（标签）
  - [ ] 是否有任何形式的评论数或评论摘要
- [ ] 记录配额：每天免费调用量多少，超了怎么算钱

**验收**：写出一页《数据可得性结论》，明确列出"我能拿到什么、拿不到什么"。
**这一步做完你会立刻踏实或者立刻调整方向，无论哪种都是赚的。**

> 💡 顺手做一件事：把返回的 JSON 原样存一份到 `raw/` 目录，永远不要覆盖。原始数据是资产。

## Phase 1 · 候选池 + 标注规范（2–3 周）

### 1.1 建候选池

- [ ] 按 6 个片区分别拉取餐饮 POI：
  - 五一广场 / 坡子街（游客核心区）
  - 南门口
  - 冬瓜山
  - 四方坪
  - 河西大学城
  - 开福区
- [ ] 清洗：去重（同名同址）、剔除连锁快餐、剔除已停业
- [ ] 得到候选池（预期 1500–3000 家）

### 1.2 分层抽样 150 家

- [ ] 按"热度代理"分层（有 rating 的用 rating × 假设评论量，没有的用标签丰富度）
- [ ] 每层各抽一部分，**不要只抽高分店**，否则没有对比度
- [ ] 硬性要求：6 个片区都要覆盖，游客区与本地生活区比例约 4:6

### 1.3 写标注规范（这一步别省）

- [ ] 定义每个维度，给出 **1 分和 5 分的锚点描述 + 真实例子**
  - 本地人认可度（1–5）
  - 游客浓度（1–5）
  - 是否网红店（是/否/疑似）
  - 是否连锁（是/否）
  - 口味标签（多选）
- [ ] 规定观察方法：看什么、怎么问、什么情况算"无法判断"
- [ ] 允许标"不确定"，并记录原因——**不确定本身就是数据**

### 1.4 先标 30 家，做一致性检验

- [ ] 自己标 30 家
- [ ] 隔一周，不看前一次结果，重标其中 10 家
- [ ] 算重测一致性（完全一致率 / 相差 1 分以内比例）
- [ ] 一致性 < 70% → 说明规范有歧义，回去改规范

**验收**：`annotation_spec.md` + 30 家标注表 + 一份一致性检验记录。

## Phase 2 · 信号可行性验证（2 周）⚠️ 生死检查点

目标：**证明或证伪"本地偏好信号"的存在。**

### 2.1 构造 3 个最容易拿到的信号

| 信号 | 计算方式 | 数据来源 |
|---|---|---|
| S1 游客核心区距离 | 店铺到五一广场的直线/路网距离 | 高德路径规划 |
| S2 片区属性 | 所属片区是游客区还是生活区 | 你自己的划分 |
| S3 结构特征 | 是否连锁、类别细分、人均价 | POI 字段 |

### 2.2 算相关性

- [ ] 对 30 家标注店，算每个信号与"本地人认可度"的 Spearman ρ
- [ ] 画散点图 / 箱线图
- [ ] 同时算"评分 vs 本地人认可度"的 ρ —— 这是你的**基线**，也是 H1 的证据

### 2.3 判断

- [ ] 若至少 1 个信号 |ρ| ≥ 0.3 → **通过**，进入 Phase 3
- [ ] 若全部 |ρ| < 0.2 → **换路线**：转 LLM 行程幻觉校验（贡献点平移，不浪费已有工作）
- [ ] 中间地带 → 扩大样本到 60 家再判一次

**验收**：一张相关性表 + 一组图 + 明确的"通过/换路线"结论。

> 这一步的价值不在结果好坏，而在于**你在 11 月底就知道了**，而不是大四才发现。

## Phase 3 · 补上两块硬数据（寒假 3 周）

### 3.1 实地客流观测（替代拿不到的历史客流）

- [ ] 选 40–50 家店，做 3 个时段观测：
  - 寒假初（本地日常）
  - 春节（游客峰值）
  - 节后（回落）
- [ ] 每次记录：排队时长、上座率、店内顾客的本地口音比例（粗估即可）、拍照打卡人数
- [ ] 用手机表格现场录入，当天回填，别靠回忆

### 3.2 评论文本（替代拿不到的 API 评论）

三个方案，按可行性排序，**建议做 A，B 作为补充**：

- **A. 放弃全量文本，只用一小批人工采样**
  从公开可见的店铺页面，人工摘录 500–1000 条评论（只记文本，不记用户信息），够算词频。
- **B. 改用公开学术数据集做方法验证**
  用 Yelp 等公开数据集跑通方法，再说明"迁移到长沙数据的可行性"。
- **C. 完全放弃文本信号**
  只保留地理 + 结构 + 实测客流。**这不是失败**，方法更简洁，且全部数据都是你自己采的，反而更硬。

- [ ] 决定走哪个方案并记录理由

### 3.3 正式标注 150 家

- [ ] 按 Phase 1 的规范完成全量标注
- [ ] 记录每家的"判断依据"一句话（答辩时这是救命的东西）

**验收**：150 家标注表 + 3 时段观测表 + 文本数据（如有）。

## Phase 4 · 实验与对比（2 周）

- [ ] 构造完整评分模型（加权 or 学习排序）
- [ ] 三条基线：评分排序 / 热度排序 / 片区随机
- [ ] 指标：Precision@10、NDCG@10
- [ ] 消融实验：逐个去掉信号
- [ ] 出图：对比柱状图、消融折线图、TPI 分布图
- [ ] 写实验记录（方法、参数、随机种子）——**可复现性**

**验收**：一份能直接搬进论文的"实验结果"章节草稿。

## Phase 5 · Java 后端服务（6–8 周，可与 Phase 4 并行）

> 只做查询与组装。数据处理留在 Python。**这条界线不要越。**

- [ ] 环境：JDK 17 + Maven + Spring Boot 3 + PostgreSQL 16 + PostGIS + Redis
- [ ] 建表：`poi`、`poi_signal`、`poi_score`、`itinerary`
- [ ] 接口（按此顺序实现，每个都要单元测试）
  - [ ] `GET /api/poi/{id}` 店铺详情
  - [ ] `GET /api/poi/search` 条件搜索 + 分页
  - [ ] `GET /api/poi/nearby` PostGIS 周边查询
  - [ ] `GET /api/poi/rank` 可信度排序（读离线算好的 score 表）
  - [ ] `POST /api/itinerary` 生成行程
  - [ ] `GET /api/itinerary/{id}` 行程详情
- [ ] 横切能力：统一响应体、全局异常处理、参数校验、日志、Redis 缓存
- [ ] Docker Compose 一键起全套
- [ ] 部署到云服务器，拿到公网 URL

**验收**：Postman/curl 能跑通全部接口；P95 延迟 < 200ms；README 能让他人复现。

## 随时警惕的四个失败模式

1. **数据没到手就开始写业务代码** → 做出来的是空壳
2. **标注规范没写就开始标** → 标到第 80 家发现前后标准不一致，全部作废
3. **Java 侧越界去做数据处理** → 两头都学不好
4. **春节不在长沙** → 提前安排代采，或改用元旦窗口做替代

## 本周就能做的三件事（按顺序，共约 4 小时）

1. **注册高德开放平台，拿 Key，调通一次 POI 搜索**（1 小时）
2. **把返回的 JSON 存下来，逐字段看一遍，回答"我到底有什么"**（1 小时）
3. **打开地图，圈出你说得出的 5 家"本地人才去、但评分不高"的店，记下名字和位置**（2 小时）

第 3 件事最重要——它是你的第一批 ground truth，也是你判断"这个项目值不值得做"的常识基准。如果连 5 家都举不出来，说明你对长沙的了解还不够支撑这个选题，那要先去吃。
